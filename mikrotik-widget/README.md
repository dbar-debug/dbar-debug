# Віджет статусу MikroTik для iPhone

Віджет на головний екран iPhone, який показує навантаження роутера MikroTik:

- **CPU** — завантаження процесора (%) з кольоровою шкалою
- **RAM** — використання пам'яті (% і МБ)
- **Трафік** — поточна швидкість ↓/↑ на WAN-інтерфейсі
- **Аптайм** — час роботи роутера

Кольори шкал: зелений < 50 %, помаранчевий < 80 %, червоний ≥ 80 %.
Якщо роутер недоступний — віджет показує червоний індикатор і текст помилки.

Реалізовано через безкоштовний застосунок **[Scriptable](https://scriptable.app)**
(App Store) — без Xcode, без збірки нативного додатка. Скрипт звертається
напряму до REST API RouterOS.

## Вимоги

- **RouterOS 7.1+** (REST API з'явився саме у v7). Перевірити версію:
  `/system resource print`
- iPhone у **тій самій мережі**, що й роутер (Wi‑Fi вдома), або доступ до
  роутера через VPN (наприклад WireGuard на самому MikroTik).

## Крок 1. Налаштувати роутер

Відкрийте термінал роутера (WinBox → New Terminal або SSH) і виконайте:

```routeros
# Окремий read-only користувач для віджета
/user group add name=widget policy=read,rest-api,api,test
/user add name=widget group=widget password=СИЛЬНИЙ_ПАРОЛЬ

# Увімкнути веб-сервіс тільки для локальної мережі
/ip service set www disabled=no address=192.168.88.0/24
```

> Політика `test` потрібна для `monitor-traffic` (швидкість на інтерфейсі).
> Якщо у вашій версії RouterOS немає політики `rest-api` — приберіть її
> зі списку, достатньо `read,api,test`.

Замініть `192.168.88.0/24` на свою підмережу. Це обмежує доступ до API лише
локальними пристроями.

**HTTPS (опційно):** якщо у вас є валідний сертифікат на роутері, увімкніть
`www-ssl` замість `www` і поставте `useHttps: true` у скрипті. Із самопідписаним
сертифікатом Scriptable працювати не буде, тому для домашньої мережі простіше
`http` + обмеження за адресою.

Перевірити, що API працює, можна з комп'ютера:

```bash
curl -u widget:ПАРОЛЬ http://192.168.88.1/rest/system/resource
```

Має повернутися JSON з полями `cpu-load`, `free-memory`, `uptime` тощо.

## Крок 2. Встановити скрипт

1. Встановіть **Scriptable** з App Store.
2. Відкрийте Scriptable → **+** → вставте вміст файлу
   [`mikrotik-status.js`](mikrotik-status.js).
3. Відредагуйте блок `CONFIG` угорі:
   - `host` — IP роутера (типово `192.168.88.1`)
   - `user` / `password` — користувач із кроку 1
   - `wanInterface` — ім'я WAN-інтерфейсу (`ether1`, `pppoe-out1` тощо;
     список: `/interface print`)
4. Запустіть скрипт кнопкою ▶ — має відкритися прев'ю віджета.
5. Назвіть скрипт, наприклад, `MikroTik Status`.

## Крок 3. Додати віджет на екран

1. Довге натискання на головному екрані → **+** (Edit → Add Widget).
2. Знайдіть **Scriptable**, оберіть малий або середній розмір.
3. Натисніть на доданий віджет → **Script** → `MikroTik Status`.

- **Малий віджет:** CPU, RAM, аптайм.
- **Середній віджет:** CPU, RAM (з МБ), швидкість ↓/↑, аптайм, модель плати.

## Оновлення даних

iOS сама вирішує, коли оновлювати віджети. Скрипт запитує оновлення кожні
5 хвилин (`refreshMinutes` у CONFIG), але фактичний інтервал може бути
5–15 хвилин — це обмеження iOS для всіх віджетів. Час останнього оновлення
показано в нижньому куті віджета.

## Доступ не з дому

Поза домашньою мережею роутер за `192.168.88.1` недоступний. Варіанти:

1. **WireGuard на MikroTik** (рекомендовано, RouterOS 7 підтримує з коробки) —
   iPhone підключається до домашньої мережі через VPN, віджет працює як удома.
2. Прокинути API назовні — **не рекомендується** з міркувань безпеки.

## Усунення несправностей

| Проблема | Причина / рішення |
|---|---|
| «Роутер недоступний» | iPhone не в домашній мережі, або сервіс `www` вимкнений, або `address=` не включає IP телефона |
| HTTP 401 | Невірний логін/пароль у CONFIG |
| HTTP 404 на `/rest/...` | RouterOS 6.x — REST API немає, потрібне оновлення до 7.1+ |
| Трафік показує «—» | Невірне ім'я `wanInterface`, або в групи користувача немає політики `test` |
| Віджет рідко оновлюється | Нормальна поведінка iOS; відкрийте Scriptable, щоб примусово оновити |
